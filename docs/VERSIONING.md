# YuKKi OS — Versioning Strategy

## Version Scheme

YuKKi OS uses a three-part version number: `MAJOR.MINOR.PATCH`

- **MAJOR** — Fundamental architectural shift (e.g., new plane model)
- **MINOR** — New capability set within the same architecture (e.g., adding sentinel quarantine)
- **PATCH** — Incremental improvements, bug fixes, performance tuning

## Migration Guide

### v6.4.3 → v6.5.0
- **Add dependency:** `x25519-dalek`, `chacha20poly1305`
- **Replace:** FNV rolling-hash transport with X25519 ECDH + ChaCha20-Poly1305 framed sessions
- **Binary rename:** `yukki_oob` → `yukki_ephemeral`

### v6.5.0 → v6.6.0
- **Add:** Sentinel quarantine registry in C layer (`sentinel_quarantine_node`, `sentinel_release_node`)
- **Add:** `chacha_weave_payload` for attractor-bound polymorphic weave
- **ABI change:** `SpatiotemporalFrame` extended with `fluidity`, `drag`, `divergence` fields — recompile C and Rust together
- **Binary rename:** `yukki_ephemeral` → `yukki_sentinel`

### v6.6.0 → v6.6.4
- v6.6.4 is an Apex Synthesis release generated by the deployment script.
- Run `scripts/deploy/deploy_yukki_6_6_4_apex.zsh` to scaffold the v6.6.4 source tree.
- New `yukki_core_node` binary replaces `yukki_sentinel`.
- Review `scripts/deploy/deploy_yukki_6_6_4_apex.zsh` for new feature flags before building.
